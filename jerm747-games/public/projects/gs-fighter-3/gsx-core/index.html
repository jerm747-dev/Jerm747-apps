What powers the game?

GSX Core is the name of Jerm747’s custom JavaScript gameplay framework. It brings together game rules, input, animation, motion, effects, audio and presentation. Three.js draws the 3D world; GSX Core connects those graphics to how the game feels and behaves.

Engine / framework
GSX Core — custom JavaScript gameplay technology using a bundled copy of Three.js r128.
Main languages
JavaScript for behavior, HTML for screen structure, CSS for layout and animation, and GLSL shaders for selected graphics effects. A small Python script rebuilds the fighter-selector page.
Graphics renderer
WebGL for GPU rendering, lighting and shadows. A custom Canvas 2D compatibility renderer is used if WebGL creation fails; it has fewer visual capabilities.
Game format
3D character models with fighting along a shared lane—often described as 2.5D gameplay. The match camera is orthographic; the post-fight showcase uses a perspective camera.
Movement & collision
Custom movement, jump arcs, spacing rules, strike-contact windows and range checks in the game code. The inspected package contains no separate general-purpose physics library.
Sound
Web Audio API: code-generated hits, blocks, swooshes, bells, V-Wave sounds, menu chimes and victory cues.

GSX Core is the engine name. “v9” identifies the technical snapshot below; the GSX Core branding is integrated in the v10 package. “r128” is the bundled Three.js revision, a separate version number.

What is inside this version?

Modes & match rules

Arcade, Training and an attract demo

Arcade is player-versus-CPU, with the first fighter to win two rounds taking the match. Options offer 30-, 60- or 99-second rounds. Training uses a passive opponent and resets after a knockout. The attract demo runs CPU versus CPU after title-screen inactivity.

Opponent AI runs locally using distance, reaction timing, aggression, blocking and weighted move choices. Difficulty levels include Easy, Normal, Hard and Ferocious.

Fighting & controls

Hands, feet, movement and V-Waves

High, mid and low punches and kicks; guard, crouch, walk, run, jumps, backflips, sweeps, airborne attacks and ranged V-Waves.

Touch controls, keyboard presets, mouse/touch menu interaction and standard gamepad input are included. Vibration and controller rumble are requested where the device and browser support them.

14 fighters: two core animation sources, Akeem and Nika, plus twelve additional rigs. The additional fighters currently reuse and retarget starter moves from Akeem and Nika, with per-fighter assignments and adjustments.

Graphics, animation and assets

Actual animated 3D meshes

Fighters use skin weights and bone skeletons. Three.js animation clips and its mixer work alongside custom pose sampling and motion blending. Runtime geometry, textures and clips are largely packed into JavaScript data files; portraits use PNG and WebP images.

The arena combines 3D geometry with painted panoramic artwork. River shimmer, stone shading, lighting and screen effects add motion and depth.

Runs on the client

The inspected game is a static browser application. Its main graphics library, scripts and artwork are bundled locally. It does not require a Node.js server to run the game.

Settings such as controls, difficulty, round length, audio and graphics use browser localStorage. Arcade-run bookkeeping is held in the current session. No account system, cloud-save service or online-match backend is present in this source package.

Browser build versus Android app

This snapshot is the browser source build. It includes Android-oriented layout behavior and detection of a GSFighterAPK user-agent marker.

The ZIP does not contain an Android manifest, Gradle project or rebuilt APK. The Android container’s implementation, permissions and minimum OS version therefore cannot be confirmed from this archive.

For web delivery, keep the extracted folders together and serve index.html from a static host. There is no offline-cache service worker in this archive, so hosted offline availability should not be assumed.

What stays useful as the game grows?

The engine explanation, component responsibilities and source map describe the game’s current foundation. Roster size, animations, artwork, quality presets, package size and presentation timings are snapshot details that may change with later builds.

The inspected v9 package’s validation includes 6 loading checks and 29 post-fight checks, plus browser checks of key screen transitions and the portrait menu. Those checks cover behavior; they are not a device-performance certification.
