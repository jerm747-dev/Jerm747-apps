RIGGING NEEDED
All nine FBX files are textured static meshes (FBX 7400). They contain no limb
skeleton, skin/cluster deformers or animation stack. Major's OBJ cannot carry
skin weights or a skeleton. None of these ten can use the combat motions yet.
Rigging in Meshy using the same humanoid workflow as Akeem/Nika would help.
Please export each as a skinned FBX with skeleton, skin weights and textures.
A neutral T-pose or one idle animation is enough for the first retargeting pass;
there is no need to export the whole animation library for each fighter.
Keep originals. These exports are dense, roughly 0.46 to 2.95 million triangles;
an optimized game mesh is useful before mobile integration. We still need to
validate skeleton axes, bind pose, proportions and deformation on arrival.

MOVE STARTING POINT PREPARED
NEW-FIGHTER-MOVE-SETS.json assigns a fixed varied set to each of the ten using
the existing Akeem/Nika motions. The random selection is performed once with a
recorded seed, so a fighter's button response stays consistent. Every planned
source mapping was checked against an actual loaded clip.
Only matching categories share candidates. The existing sweep is shared.
The low-kick starting point is Nika's knee strike; no dedicated shin kick was
supplied. Some low-punch choices are still jabs/hooks that visibly hit higher.
After retargeting, reaction choice must follow actual hit location/direction.
The existing short, adaptive reaction families can then be reused on each rig.
Source rigs, clip names, playback rates and sweep trim are recorded in JSON.

STATUS
